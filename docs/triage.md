# triage — мінімальний асистент зі структурованим виходом

Стартовий код до практичної «Мінімальний асистент зі структурованим виходом». Асистент розбирає звернення клієнта у валідований структурований об'єкт, визначає, хто обробить звернення, і повідомляє клієнту, що буде далі. Умова, вимоги варіантів, критерії приймання й рубрика — в умові практичної в матеріалах курсу.

Тут лише каркас: розв'язку немає. Зразки патернів — у [репозиторії демо](https://github.com/pseudochaos/support-assistant-demo), але демо не є розв'язком: у ньому немає ні вимоги вашого варіанта, ні специфікації, ні журналу, ні регресійного набору.

## Фейкова модель

`FakeModel` з `tests/starter/fakes.py` підміняє постачальника в тестах: повертає наперед задані відповіді по черзі й запам'ятовує, що отримала (`model.received`). Імпортується з будь-якого тесту як `from fakes import FakeModel`. Відповідь може бути:

- екземпляром вашої схеми — валідний структурований вихід;
- `InvalidOutput("текст")` — вихід, що не проходить валідацію;
- винятком, наприклад `TimeoutError(...)`, — збій постачальника, який модель кидає як є;
- рядком — звичайна текстова відповідь.

`with_structured_output(..., include_raw=True)` повертає те саме, що справжня модель: `raw`, `parsed` і `parsing_error`, а в `raw.usage_metadata` — токени для журналу. Приклади — у `tests/starter/test_starter_fakes.py`.
